# Kailash Energy CRM｜三大仪表盘逻辑 V2

本方案复用飞书多维表格的两张业务表：客户档案 `tblbk7Ju6fcM1BXF`、客户沟通与跟进 `tblNi7C5q5FYlG06`。禁止为图表重复创建客户主表。

## 数据安全与统计前提

- 客户以 `Shopify客户ID`（完整 GID）去重，只统计标记「有效」的 CRM 客户。
- 所有近180天金额/订单/最近购买时间必须来自完整 Shopify 有效订单快照；缺失时为「待计算」，不能填0。
- 分层顺序 S+→S→A→B，三条件同时满足；RFM 八组独立于 CRM 价值等级。
- 订阅按 Shopify 实际营销状态区分，未订阅和已退订记录可以用于客服及RFM，不能用于未经同意的营销。
- 公开或员工概览只呈现汇总指标；客户邮箱、订单、沟通内容不进入公开分析接口。

## A｜客户价值与 RFM 大盘

**筛选器**：统计日期、CRM等级、RFM分群、邮件订阅状态、客单价组、国家/地区、客户负责人。

| 组件 | 指标与展示 | 统计规则 |
| --- | --- | --- |
| KPI 1 | 有效客户数 | 有效且 Shopify GID 唯一 |
| KPI 2 | 近180天净销售 | 仅当所有有效客户M已核验才展示完整总额；否则展示「待计算」与已核验覆盖率 |
| KPI 3 | 近180天有效订单数 | 同上，F 完整才展示总量 |
| KPI 4 | 复购客户数/率 | 至少2笔有效订单的人数/有效已购客户数；指标保留快照日期 |
| 横条图 | S+、S、A、B、基础、沉睡、从未购买、待核验 | 人数及占比，等级结果不从历史累计消费推断 |
| 横条图 | RFM 八大分群 | 高R=90天内购买，高F=180天至少2单，高M=180天净消费≥$800（初始阈值） |
| 堆叠图 | CRM等级×订阅状态 | 仅计真实 Shopify marketingState |
| 趋势图 | 价值等级迁移、新增、沉睡 | 需按日期保存每日快照，不能把当前状态伪装成历史趋势 |

**点击联动**：选择某个等级/分群后，打开客户档案对应筛选视图；客户记录保留一对一维护链接。

## B｜客户关系健康与维护大盘

**筛选器**：CRM等级、关系健康度、负责人、待维护期限、生命周期。

| 组件 | 指标与展示 | 统计规则 |
| --- | --- | --- |
| KPI | 健康/关注/风险人数 | 只有被证据和规则支持的关系健康字段才计入，展示覆盖率 |
| 矩阵 | CRM等级×关系健康度 | 高价值风险客户最优先；未知不归健康 |
| KPI | 已分配负责人占比 | 有负责人字段的有效客户/有效客户总数 |
| 待办 | 建议维护日期已过 | 需结合沟通任务确认是否真正逾期，概览标为「待复核到期维护」 |
| 列表 | S+维护、客户升级、投诉风险、潜在复购 | 需要后续人工任务、客户反馈、订单事件的真实记录 |

**决策输出**：客户为什么需要维护、目前证据、优先负责人、下一步最佳行动（NBA）；不得把AI推测当作客户事实。

## C｜客服与跟进效率大盘

**筛选器**：最近7/30/90天、渠道、问题类型、优先级、负责人、任务状态。

| 组件 | 指标与展示 | 统计规则 |
| --- | --- | --- |
| KPI | 有效沟通数 | 只统计对应日期范围内的记录 |
| KPI | 待处理/处理中/等待客户 | 按飞书任务状态字段统计 |
| KPI | 未关闭记录 | 状态不为已完成/已取消，未知状态保留待核验 |
| KPI | 平均处理时长 | 仅使用有真实处理时长的记录，展示样本数 |
| 横条图 | 问题类型/渠道/优先级 | 按真实字段分组，空值为未分类 |
| 趋势图 | 新增、解决和逾期变化 | 需每日快照；缺历史快照时不伪造趋势 |

## 技术落地状态

- `lib/crm-dashboard-metrics.js`：聚合逻辑（已建立），不读取客户隐私之外的字段。
- `api/crm-dashboard-data.js`：受保护的汇总接口；要求后台 Bearer Token，仅供内部授权调用。
- 飞书原生仪表盘图表：需在飞书界面配置或使用经验证可写的官方接口；创建完成前不得标记为已完成。
- 尚未具备完整M/R/F、关系健康与沟通数据的图表应显示数据覆盖率及待核验状态。
